# memebox 工具箱

基于 uni-app（Vue 3）开发的移动端小工具箱。目前包含图像隐藏工具**幻影坦克**、**光棱坦克**，素材生成工具**摸头表情**、**魔法阵**，
以及二维码生成、计算器等常用小工具。

## 功能一览


| 工具         | 说明                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| **幻影坦克** | 把两张图合成一张带透明通道的 PNG：白色背景下显示其中一张，黑色背景下显示另一张。含「编码」「解码」两个模式 |
| **光棱坦克** | 把两张图编码进一张不透明图片：正常观看是一张图，显形后是另一张。含「制作」「显形」两个模式                 |
| **摸头表情** | 上传头像，按五帧手部动作合成循环 GIF，可调头像大小、压扁、水平翻转与帧延时                               |
| **魔法阵**   | 按预设 + 随机种子生成发光魔法阵，可加自定义铭文与图片，保存透明底 / 黑底 PNG 与旋转的循环 GIF                |
| 二维码       | 文本生成二维码，四档容错级别，可保存图片                                                                   |
| 计算器       | 四则运算，支持百分号、正负号、退格、清空                                                                   |

各部分的实际验证状态见文末「平台支持与验证状态」——功能已实现，不等于已在真机上跑通。

## 幻影坦克

### 原理

像素的透明度由「白底可见」的那张图决定，颜色由「黑底可见」的那张图决定，输出为带 alpha
通道的 PNG。更换背景色即可看到另一张图。

### 编码

- **选图**：「白底可见」「黑底可见」两张。左图决定输出的尺寸与比例，右图按其比例居中裁剪，
  因此两张尺寸不同也可使用；支持交换两张图。
- **灰度模式**（默认开启）：灰度是唯一能同时精确还原两张图的模式。关闭后黑底图保留颜色，
  白底图会变成「黑底图加一层亮度偏移」。
- **反相**：白底图、黑底图各一个开关。
- **亮度**：白底图、黑底图各一个滑块。
- **长边上限**：720 / 1080 / 1440，值越大越清晰，处理耗时也越长。
- 生成后可保存图片。

生成后页面会给出两张图在两个背景下的**平均亮度差**（0～255），这是效果强度的判断依据：
低于 10 时，两个背景下的观感基本没有区别。

### 解码

选择一张幻影坦克图片后自动解析，在 JS 中分别按白底与黑底合成并给出两张预览，可分别保存为
不透明 PNG。合成在 JS 内完成，不依赖渲染层对透明通道的处理，因此不受系统相册、浏览器白底
等固定背景的影响。

## 光棱坦克

### 原理

两张图按棋盘格交错编码：**表图**的像素全部落在亮度较高的一段，**里图**的像素全部落在较低的
一段，两者不重叠。因此显形时按亮度带即可将两张图分开，不需要任何启发式判断。

### 制作

- **表图 / 里图**两张源图。
- **里图色阶端**：里图的亮度被压进 `0 ~ 色阶端`，显形时再把这一个区间拉伸回全量程。该值必须
  小于表图色阶端，否则两张图的亮度带会重叠。值越大里图还原越准确，代价是正常观看时噪点更明显。
- **反相**：把两张图的亮度带对调，显形阈值随之变化，制作完成后会自动填入显形侧。
- **颜色模式**：默认表图转灰度、里图保留颜色。
- **里图对比度**：制作时先给里图提升对比度，它才有足够的动态范围挤进那条只有几十级的窄带；
  里图本身对比度较低时，这一步对显形质量的提升最明显。
- **表图对比度**：只影响正常观看时的观感，**不写入元数据**，因此显形侧不会自动还原它。
- **间隔 / 斜率**：条纹占 N 格、空 1 格，因此里图占 `1/(N+1)` 的像素。间隔越大表图越完整，
  但里图可用的采样点越少。
- **长边上限**：720 / 1080 / 1440。

### 显形

- 选择一张光棱坦克图片后自动显形：把亮度落在阈值区间内的像素拉伸回全量程。
- **阈值来源**依次为：图片自带的元数据 → 从图片本身反推 → 手动填写或按上次制作的参数预填。
- 可调阈值区间、区间外像素的处理方式（扩散填充 / 黑色 / 白色 / 透明）、对比度还原。
- **按原尺寸显形**（默认开启）：直接使用源图原始像素，不做任何缩放。
- 显形结果可保存。

### 元数据

制作参数（里图的对比度等）会写入 PNG 的 `tEXt` 数据块。因此将自己制作的图片交给他人后，
对方用本工具打开即可自动显形，无需手动调参。元数据丢失时（图片被重新压缩过），工具会改为
直接从图片本身反推阈值。预设格式与 `tEXt` 块的写法与参考实现互通，详见「第三方代码」。

## 摸头表情

### 原理

把上传的头像贴进五帧手部动作素材里，逐帧合成 112×112 的透明动画帧，最后编码成循环 GIF。
五帧素材以 base64 内嵌在代码中，不经过任何平台 API 读取。

### 制作

- **头像**：选一张图，按比例裁成正方形后贴入。
- **头像大小**：头像在画面中的占比。
- **压扁**：头像横向压扁的程度，1 为不压扁。
- **水平翻转**：左右镜像。
- **帧延时**：每帧停留的时长，直接决定 GIF 的播放速度。

### 预览与保存

- 预览区把五帧**压平到白底**后轮换播放。这是有意为之：App 端的 `<image>` 无法把父容器的
  背景从 PNG 的透明区域透出来，直接显示带透明的帧会是一块怪东西。**实际保存的 GIF 仍然
  带透明通道**，压平只发生在预览这一步。
- 预览只是展示效果。**判断「GIF 到底动没动」请看成品区** —— 那里贴的就是即将保存的那份
  数据，与预览不是一回事。
- 保存后可在系统相册中查看动画效果。

## 魔法阵

### 原理

整张图是**算出来**的，不是画出来的：每个图元（圆环 / 星形多边形 / 刻度 / 符文带 / 断续弧）
算一遍「每个像素到它的距离」，再按距离推覆盖率得到抗锯齿的边缘，最后把模糊过的 alpha 当一层
光晕垫在线条下面。全程在纯 JS 里做，不经过 canvas，所以输出的透明通道是逐字节精确的。

### 阵型与种子

- **预设**：五芒星、六芒星、时钟、元素、混沌、圣光。每套的骨架是写死的。
- **换一个**：重新掷一个种子。**同一个种子永远给出同一张图**，页面会把种子号显示出来。
- 随机只在预设给定的结构里摆动（哪些可选图层出现、几个二选一的取值、符文字形长什么样），
  不会凭空发明结构 —— 这是刻意的，否则很容易退化成「一堆随机圆环」。

### 参数

- **复杂度**：图层数，从只有外圈和主星形的骨架，到加上内环、符文带、反向旋转的细弧。
- **线宽**：以阵半径的千分比计，所以换个输出尺寸粗细比例不变。
- **辉光**：0 就是纯线条；调大时最亮处的光晕不透明度上升，但不会糊成一片实心。
- **符文密度**：符文带上的字符条数。符文不是固定的几十个字形，而是按真实符文的构字法
  （一条竖主干加 1~3 条斜枝、坐标吸附到粗网格）生成的，所以每次都不同、但都读得出是符文。

### 铭文与图片

- **铭文**：沿外圈排一行文字，可调半径和大小。
  - 英文字母、数字和常用符号用**内置的矢量描边字体** —— 各端完全一致，而且风格和符文带是同一套（细线刻痕）。只有大写，输入会自动转大写。
  - 中文会借系统字体渲染，**字形随设备变**（这是唯一一处同一个参数在不同手机上结果不同的地方）。字体里没有的字会画成一个方框，页面上会提示有几个。
- **中心图**：裁成圆形放在阵心，不跟随旋转。阵的线条压在它上面把它框住。
- **环绕图**：沿一圈排开，可选「同图环绕」（一张铺满）或「依次排开」（多张轮流占位）。
- 图片和文字都是**额外叠加**的，不加也完全能用 —— 加了之后「同一个种子出同一张图」就不再成立（用户传的东西不属于种子）。

### 保存

- **PNG**：可选黑底或透明底，长边 720 / 1080 / 1440。
- **GIF**：旋转的循环动画，可选帧数与边长。
  - 动画的循环无缝是**构造性**的：每层的转速都是「每个循环转整数圈」，所以循环走完必然回到
    起点，接缝处不会跳。
  - **动图恒为黑底**。GIF 的透明只有「透明 / 不透明」两档，装不下辉光那种从 0 渐变的
    半透明，硬要透明输出会把光晕截成一圈硬边 —— 这是格式的限制，不是参数没调好。

## 使用须知

图片经聊天软件按「图片」发送时会被重新压缩，以上几个工具的产物都会受影响：幻影坦克的透明
通道会被拍平，光棱坦克只有几十级的亮度带会被抹平，写入的元数据也会一并丢失；摸头表情的
GIF 在部分查看器里可能只显示第一帧；魔法阵是细线条，重压缩后线条会糊、辉光会断。

1. **发送与保存请使用「原图」或「文件」方式**，不要按普通图片发送。
2. **请在能看到深浅两种背景的环境下查看**（如聊天气泡与点开后的全屏大图）。在系统相册、
   浏览器白底等背景固定的查看器中，透明 PNG 与普通图片无异。

## 开发与运行

本项目由 HBuilderX 管理，**没有 `package.json`，不需要也无法通过 `npm install` 安装依赖**。

- 开发调试：用 HBuilderX 打开项目 →「运行」→ 浏览器 / 微信开发者工具 / 手机真机
- 发布：「发行」→ 打包 App 或上传小程序

App 端需在 `manifest.json` 中声明 `Gallery` 与 `Camera` 模块（相册、相机）。修改过
`manifest.json` 的权限或模块配置后，真机调试需重新制作自定义调试基座；普通「运行到手机」
使用的是标准基座，不会更新原生配置。

### 纯逻辑可以脱离平台测试

`test/` 下的脚本可在**没有 node、没有 npm** 的环境下运行——VS Code 自带的 Electron 可以当 node 用：

```bash
CODE="/c/Users/HauntZone/AppData/Local/Programs/Microsoft VS Code/Code.exe"

T=$(mktemp -d)
cp common/prismTank.js common/imageGeometry.js common/phantomTank.js \
   common/pngWriter.js common/pngReader.js common/pako.js "$T/"
cp test/tanks.test.mjs "$T/"
printf '{"type":"module"}' > "$T/package.json"

ELECTRON_RUN_AS_NODE=1 "$CODE" "$T/tanks.test.mjs"
```

退出码为 0 即全部通过。详细说明与「不要退化掉的几处」见 [test/README.md](test/README.md)。

摸头表情的纯逻辑（五帧合成、中位切分量化、GIF 编码）另有一套测试，多复制几个模块即可：

```bash
T=$(mktemp -d)
cp common/petpet.js common/imageGeometry.js common/colorQuantize.js common/gifWriter.js \
   common/petpetHands.js common/pngReader.js common/pako.js "$T/"
cp test/petpet.test.mjs "$T/"
printf '{"type":"module"}' > "$T/package.json"

ELECTRON_RUN_AS_NODE=1 "$CODE" "$T/petpet.test.mjs"
```

魔法阵的纯逻辑（光栅化、符文、图层与渲染、逐帧、GIF 组装）也有一套：

```bash
T=$(mktemp -d)
cp common/magicShape.js common/magicRunes.js common/magicFont.js common/magicText.js \
   common/magicCircle.js common/imageGeometry.js common/colorQuantize.js common/gifWriter.js "$T/"
cp test/magicCircle.test.mjs "$T/"
printf '{"type":"module"}' > "$T/package.json"

ELECTRON_RUN_AS_NODE=1 "$CODE" "$T/magicCircle.test.mjs"
```

它会顺带打印性能基准（各尺寸渲染耗时、默认档 GIF 的组装耗时与体积），改动画参数后可以对比。

## 项目结构

```
pages/
  index/          首页。主包只保留它一个页面，启动最快
  tools/          分包：二维码、计算器
  image/          分包：幻影坦克、光棱坦克、摸头表情、魔法阵
                  （四者共用同一套图像内核与 PNG / GIF 编码，因此放在同一分包）
components/       tool-slider：自研触摸滑块（原生 <slider> 的圆点过小，难以按准）
common/
  phantomTank.js   幻影坦克算法        ┐
  prismTank.js     光棱坦克算法        │
  petpet.js        摸头表情五帧合成     │ 纯逻辑：不涉及 uni.* / DOM，
  imageGeometry.js 尺寸/裁剪/合成/降采样 │ 输入输出均为普通数据结构，可直接测试
  colorQuantize.js 中位切分量化        │
  gifWriter.js     GIF89a 容器 + LZW   │
  calculator.js    计算器              │
  sliderMath.js    滑块取值换算         ┘
  petpetHands.js   五帧手部素材（base64 内嵌；放 static/ 会读不到，原因见 CLAUDE.md）
  magicShape.js    光栅化原语（距离场覆盖率、描边、贴图、模糊、辉光）┐ 魔法阵专用；
  magicRunes.js    符文的构字法生成                              │ 与另外三个工具
  magicFont.js     矢量描边字体（纯数据，只有大写）               │ **不共用图像内核**
  magicText.js     字形解析 / 环上排版 / 光栅化排版（纯逻辑）      │
  magicCircle.js   图层模型 / 预设 / 渲染 / 逐帧 / GIF 组装        ┘
  pngReader.js    从文件字节纯 JS 解 PNG ┐
  pngWriter.js    手写 PNG 字节（含 tEXt）│ 平台无关，但只在平台流程中使用
  pako.js         deflate（vendored）    ┘
  imagePlatform.js  **唯一的平台代码**：选图 / 读像素 / 导出文件 / 存相册
  *Adapter.js       薄壳，把 canvas id 与文件名前缀填入上面那个文件
```

## 平台支持与验证状态

本项目主要面向 **App 端**。


| 部分                                               | 状态                                                 |
| -------------------------------------------------- | ---------------------------------------------------- |
| 幻影坦克（编码 → 导出 → 存相册 → 外部查看 → 解码） | Android 真机 + H5 跑通                               |
| 摸头表情（合成 → 预览 → 导出 GIF → 存相册）        | Android 真机 + H5 跑通；保存到相册后 GIF 正常播放    |
| 魔法阵（生成 → 预览 → 保存 PNG / GIF）             | 基础版在 Android 真机 + H5 跑通；相册中 GIF 正常播放，透明底 PNG 干净 |
| 魔法阵的铭文与图片（2026-10-08 新增）              | 纯逻辑已测（注入式）；**页面与平台层一次都没跑过**   |
| 光棱坦克（制作 / 显形）                            | 实测中发现部分功能有问题，已搁置待排查               |
| iOS 端的平台分支                                   | 未验证                                               |
| 微信小程序的平台分支                               | 未验证                                               |

综上，目前 **Android 真机**与 **H5** 两条路径上，幻影坦克、摸头表情与魔法阵的完整流程均已跑通；
光棱坦克在实测中发现问题、暂时搁置；魔法阵的**铭文与图片**是 2026-10-08 新加的，纯逻辑有测试
顶着（图片和字形蒙版按注入式测），但页面与平台层**一次都没跑过**；iOS 与微信小程序的平台分支
尚未经过运行验证，**这些部分可能存在尚未暴露的平台问题**，欢迎通过 issue 反馈。

各页面内均提供「环境诊断」面板（平台、最近一次错误等），反馈问题时请一并附上，
其价值高于对现象的文字描述。需要读像素的页面还会显示 canvas 节点与读到的像素数；
魔法阵不读像素，所以它那一页刻意不显示这些字段（会显示成上一个页面的陈旧读数、反而误导）。
