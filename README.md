# memebox 工具箱

基于 uni-app（Vue 3）开发的移动端小工具箱，包含图像隐藏工具**幻影坦克**、**光棱坦克**，
素材生成工具**摸头表情**、**魔法阵**，以及二维码生成、计算器等常用小工具。

## 功能一览

| 工具         | 说明                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| **幻影坦克** | 把两张图合成一张带透明通道的 PNG：白色背景下显示其中一张，黑色背景下显示另一张。含「编码」「解码」两个模式 |
| **光棱坦克** | 把两张图编码进一张不透明图片：正常观看是一张图，显形后是另一张。含「制作」「显形」两个模式                 |
| **摸头表情** | 上传头像，按五帧手部动作合成循环 GIF，可调头像大小、压扁、水平翻转与帧延时                                 |
| **魔法阵**   | 按预设 + 随机种子生成发光魔法阵，可加自定义铭文与图片，保存透明底 / 黑底 PNG 与旋转的循环 GIF              |
| 二维码       | 文本生成二维码，四档容错级别，可保存图片                                                                   |
| 计算器       | 四则运算，支持百分号、正负号、退格、清空                                                                   |

## 幻影坦克

### 编码

- **选图**：「白底可见」「黑底可见」两张。左图决定输出的尺寸与比例，右图按其比例居中裁剪，
  因此两张尺寸不同也可使用；支持交换两张图。
- **灰度模式**（默认开启）：同时精确还原两张图。
- **反相**：白底图、黑底图各一个开关。
- **亮度**：白底图、黑底图各一个滑块。
- **长边上限**：720 / 1080 / 1440，值越大越清晰，处理耗时也越长。
- 生成后可保存图片。

生成后页面会给出两张图在两个背景下的**平均亮度差**（0～255），这是效果强度的判断依据：
低于 10 时，两个背景下的观感基本没有区别。

### 解码

选择一张幻影坦克图片后自动解析，分别按白底与黑底合成并给出两张预览，可分别保存为不透明 PNG。

## 光棱坦克

### 制作

- **表图 / 里图**两张源图。
- **里图色阶端**：值越大里图还原越准确，代价是正常观看时噪点更明显。
- **反相**：把两张图的亮度带对调，制作完成后会自动填入显形侧。
- **颜色模式**：默认表图转灰度、里图保留颜色。
- **里图对比度**：里图本身对比度较低时，提升它对显形质量的改善最明显。
- **表图对比度**：只影响正常观看时的观感，不会写入元数据。
- **间隔 / 斜率**：间隔越大表图越完整，但里图可用的采样点越少。
- **长边上限**：720 / 1080 / 1440。

### 显形

- 选择一张光棱坦克图片后自动显形。
- **阈值来源**依次为：图片自带的元数据 → 从图片本身反推 → 手动填写或按上次制作的参数预填。
- 可调阈值区间、区间外像素的处理方式（扩散填充 / 黑色 / 白色 / 透明）、对比度还原。
- **按原尺寸显形**（默认开启）：直接使用源图原始像素，不做任何缩放。
- 显形结果可保存。

### 元数据

制作参数会写入 PNG 的 `tEXt` 数据块。因此将自己制作的图片交给他人后，对方用本工具打开即可
自动显形，无需手动调参。元数据丢失时（图片被重新压缩过），工具会改为直接从图片本身反推阈值。

## 摸头表情

### 制作

- **头像**：选一张图，按比例裁成正方形后贴入。
- **头像大小**：头像在画面中的占比。
- **压扁**：头像横向压扁的程度，1 为不压扁。
- **水平翻转**：左右镜像。
- **帧延时**：每帧停留的时长，直接决定 GIF 的播放速度。

### 预览与保存

- 预览区把五帧**压平到白底**后轮换播放，只用于展示效果。**判断「GIF 到底动没动」请看成品区**
  ——那里贴的就是即将保存的那份数据。**实际保存的 GIF 仍然带透明通道**。
- 保存后可在系统相册中查看动画效果。

## 魔法阵

### 阵型与种子

- **预设**：五芒星、六芒星、时钟、元素、混沌、圣光。
- **换一个**：重新掷一个种子。**同一个种子永远给出同一张图**，页面会把种子号显示出来。
- 随机只在预设给定的结构里摆动，不会凭空发明结构。

### 参数

- **复杂度**：图层数。
- **线宽**：以阵半径的千分比计，所以换个输出尺寸粗细比例不变。
- **辉光**：0 就是纯线条。
- **符文密度**：符文带上的字符条数。

### 铭文与图片

- **铭文**：沿外圈排一行文字，可调半径和大小。
  - 英文字母、数字和常用符号用**内置的矢量描边字体**，各端完全一致，只有大写，输入会自动转大写。
  - 中文会借系统字体渲染，**字形随设备变**。字体里没有的字会画成一个方框，页面上会提示有几个。
- **中心图**：裁成圆形放在阵心，不跟随旋转。
- **环绕图**：沿一圈排开，可选「同图环绕」（一张铺满）或「依次排开」（多张轮流占位）。
- 图片和文字都是**额外叠加**的，不加也完全能用 —— 加了之后「同一个种子出同一张图」就不再成立。

### 保存

- **PNG**：可选黑底或透明底，长边 720 / 1080 / 1440。
- **GIF**：旋转的循环动画，可选帧数与边长。**动图恒为黑底**。

## 使用须知

图片经聊天软件按「图片」发送时会被重新压缩，以上几个工具的产物都会受影响：幻影坦克的透明
通道会被拍平，光棱坦克的亮度带会被抹平，写入的元数据也会一并丢失；摸头表情的 GIF 在部分
查看器里可能只显示第一帧；魔法阵是细线条，重压缩后线条会糊、辉光会断。

1. **发送与保存请使用「原图」或「文件」方式**，不要按普通图片发送。
2. **请在能看到深浅两种背景的环境下查看**（如聊天气泡与点开后的全屏大图）。在系统相册、
   浏览器白底等背景固定的查看器中，透明 PNG 与普通图片无异。

## 项目结构

```
pages/
  index/          首页。主包只保留它一个页面，启动最快
  tools/          分包：二维码、计算器
  image/          分包：幻影坦克、光棱坦克、摸头表情、魔法阵
                  （四者共用同一套图像内核与 PNG / GIF 编码，因此放在同一分包）
components/       tool-slider：自研触摸滑块（原生 <slider> 的圆点过小，难以按准）
common/
  phantomTank.js   幻影坦克算法        ┐
  prismTank.js     光棱坦克算法        │
  petpet.js        摸头表情五帧合成     │ 纯逻辑：不涉及 uni.* / DOM，
  imageGeometry.js 尺寸/裁剪/合成/降采样 │ 输入输出均为普通数据结构，可直接测试
  colorQuantize.js 中位切分量化        │
  gifWriter.js     GIF89a 容器 + LZW   │
  calculator.js    计算器              │
  sliderMath.js    滑块取值换算         ┘
  petpetHands.js   五帧手部素材（base64 内嵌）
  magicShape.js    光栅化原语（距离场覆盖率、描边、贴图、模糊、辉光）┐ 魔法阵专用；
  magicRunes.js    符文的构字法生成                              │ 与另外三个工具
  magicFont.js     矢量描边字体（纯数据，只有大写）               │ 不共用图像内核
  magicText.js     字形解析 / 环上排版 / 光栅化排版（纯逻辑）      │
  magicCircle.js   图层模型 / 预设 / 渲染 / 逐帧 / GIF 组装        ┘
  pngReader.js    从文件字节纯 JS 解 PNG ┐
  pngWriter.js    手写 PNG 字节（含 tEXt）│ 平台无关，但只在平台流程中使用
  pako.js         deflate（vendored）    ┘
  imagePlatform.js  **唯一的平台代码**：选图 / 读像素 / 导出文件 / 存相册
  *Adapter.js       薄壳，把 canvas id 与文件名前缀填入上面那个文件
```
